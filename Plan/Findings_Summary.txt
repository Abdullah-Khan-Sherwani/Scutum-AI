F44   SQL Injection - Authentication Bypass on Login       Critical         CWE-89
F45   Broken Access Control (IDOR) on Basket Endpoint       High            CWE-639
------------------------------------------------------------------------------------------------------------------------

F44 -- SQL Injection - Authentication Bypass
  Endpoint:        POST /rest/user/login
  Payload sent:    {"email": "' OR 1=1--", "password": "x"}
  Server response: HTTP 200, valid signed JWT decoding to
                   {"email":"admin@juice-sh.op","role":"admin", ...}
  Root cause:      user-supplied email concatenated directly into the login SQL query; the injected
                   OR 1=1-- clause matches the first user row and comments out the password check.
  Impact:          full administrative account takeover with no valid credentials.
  Remediation:     parameterized queries / prepared statements for all authentication logic.
  CVE/Exploit-DB:  not applicable -- custom application-logic flaw, not a versioned public package defect.

F45 -- Broken Access Control / IDOR on Basket Endpoint
  Endpoint:        GET /rest/basket/{id}
  Setup:           agent registered + logged in as its own test account (UserId 25, own basket id 6)
  Request sent:    GET /rest/basket/5 (a different sequential ID), using its own valid auth token
  Server response: HTTP 200, returned basket data belonging to a different user (UserId 16), including
                   real product contents and quantities
  Root cause:      the endpoint checks for a valid session token but never verifies the requested basket
                   ID actually belongs to that session's user.
  Impact:          horizontal privilege escalation -- any authenticated user can read other users' baskets.
  Remediation:     enforce basket.UserId == session.UserId on every object-referencing endpoint.
  CVE/Exploit-DB:  not applicable, for the same reason as F44.
